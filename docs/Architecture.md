# Scene and collaboration boundaries

The implementation has a .NET 10 Blazor WebAssembly editor and typed document rules, an original Canvas renderer/exporter, and a Cloudflare Pages Functions/D1 service. The renderer receives only a validated finite scene vocabulary: no uploaded images, external URLs, arbitrary SVG or JavaScript. A film contains a cast and ordered shots; each shot has a duration, stage, actor performance and timed caption beats. Cloudflare was selected because bounded JSON snapshots and SQLite transactions fit the real workflow without a media host or paid server. It is a deployment dependency, not an interchange format: JSON and HTML exports remain independent.

Local documents do not require an account. Browser storage is a convenience, and explicit JSON export owns the portable copy. The HTML export embeds the film and the first-party renderer, with script-closing characters encoded. WebM is a real-time browser recording and must stop visibly on interruption.

Private projects have owner/editor/viewer roles, expected-revision saves and durable versions. Invites are one-use capabilities, stored as hashes. Public cuts are immutable snapshots with a pinned parent cut and explicit reuse permission; private project history is never projected to public records. Reports and withdrawal affect public serving, not another author's already exported or lawfully forked copy. Public content contains no private project identifiers or membership lists.

The browser and server validate independently. Canonical film JSON has a 96 KiB UTF-8 limit, 1–6 cast members, 1–12 shots, 1–4 performers per shot, 0–8 caption beats per shot, 3–15 seconds per shot and 90 seconds total. Stable actor/shot/caption identifiers preserve references. Same-actor caption overlap, unknown vocabulary, non-finite/out-of-range movement and unexpected fields are refused. C# exports compact JSON so the file written by the editor fits its own import limit.

Each shared save uses a project revision and unique write identity. The same successful identity can be recovered after an uncertain response; a different payload cannot reuse it. Current owner/editor membership is tested inside the SQL update, including after a streamed body pauses. The accompanying immutable version insert is in the same D1 batch. The client retains its edited revision rather than silently adopting a newer concurrent revision as its baseline.

Public cuts copy a saved owner-controlled revision, never unsaved browser state. They store canonical and creative hashes. The creative projection ignores title, synopsis and identifier-only changes; unchanged/title-only forks are refused. Public requests receive the film, publisher alias, source hash and computed change summary, excluding private project identifiers, invite capabilities and member lists. Withdrawal does not mutate the snapshot or unpublish an already licensed descendant. Account deletion withdraws/anonymizes that account's cuts while cascading owned private projects/sessions.

Browser page selection and account generations guard late responses. A slow invitation/publication/deletion result cannot appear under a different selected project; consumer tests invoke the actual compiled Razor component with the HTTP await paused. The test layer contains its own transport and does not change production classes.
